# 登録ナンバーの窓口（Cloudflare Workers）

アプリの登録ナンバーを、利用者ごとに重複しないものにするための窓口。

**持っているのは「その5桁が使われているか」だけ。** 氏名も連絡先も扱わない。

- 本体：`https://suzu-plate.bebebe-coder.workers.dev`
- 保管庫：**Durable Objects**（クラス `PlateBook`。無料枠で使えるSQLite版）

## 番号の形

本物のナンバープレートに合わせてある。

```
あ・・61     ← ひらがな1字 ＋ 1〜9999 の数字（4桁に満たないぶんは中点）
```

| 位置 | 中身 | 通り数 |
|---|---|---|
| 1文字目 | ひらがな。**あ〜わ から お・し・へ・ん を除いた41字**。尽きたら A〜Z | 67 |
| 2〜5文字目 | 1〜9999 の数字。**先頭の0は詰める**（本物に `0115` は無く、`115` は `・115` と出る） | 9,999 |

組み合わせは **約67万通り**。希望の数字を出すと、まだ使われていない文字が自動で付く。

## 窓口

いずれも `Origin` が許可されたサイトでないと 403。

| | 内容 |
|---|---|
| `GET /v1/check?n=61` | 空いている最初の文字を返す（読み取りのみ） |
| `POST /v1/claim` `{"n":"61"}` | 確保して、番号と**再発行キー**を返す |
| `POST /v1/verify` `{"n","mark","key"}` | その番号が本人のものか確かめる |

再発行キーは**そのまま保管しない**。SHA-256 にしてから置いている。

## 保管の仕組み（2026-11-02にKVから移した）

**数字1つにつき、世界で1つだけの台帳**が割り当てられる（`idFromName('n:' + 数字)`）。
その数字への確認も確保も必ずそこへ集まり、**1件ずつ順番に**処理される。
行列が1本になるので、同時に来ても同じ文字が出ない。

以前は Workers KV に置いていた。KVは世界中の拠点に写しが置かれる仕組みで、
書いた内容が全拠点へ行き渡るまで時間差がある。そのため
「あ は空いている」と2人が同時に見てしまう隙が、ごく稀に残っていた。

| | Workers KV（〜v13） | Durable Objects（v14〜） |
|---|---|---|
| 置かれ方 | 全拠点に写し | **世界に1つ** |
| 読み書き | 速いが**反映に時間差** | **順番が守られる** |
| 書き込み枠 | 1日1,000回 | この枠から外れる |
| 同じ文字の重複 | ごく稀に起きうる | **起きない** |

台帳が持つのは、使用済みの文字をまとめた `taken` と、文字ごとの `m:<文字>`（確保日時と鍵のハッシュ）だけ。
2つの書き込みは1回の `storage.put` でまとめて渡すので、片方だけが残ることはない。

**実測（2026-11-02）**：同じ数字「61」を8件同時に確保させたところ、
あ・い・う・え・か・き・く・け が1つずつ配られ、重複ゼロ。9文字目の空きは「こ」。

## 回数の制限

| | 上限 |
|---|---|
| 窓口ぜんたい | 1つのIPから **1分60回** |
| 確保のみ | 1つのIPから **1時間10回** |
| 確保のみ | 全体で **1日1,000件**（Workers自体の無料枠=1日10万リクエストを守るため） |

数えるのに **Cache API** を使っている。保管庫側の枠を使わずに数えられるため。

**Cloudflare の rate limiting バインディング（unsafe）も試したが、この構成では効かなかった。**
1分20回の設定で45回続けても1度も止まらないことを実測している。
いまの作りは Cache API によるもので、こちらは実測で止まることを確認済み。

ただし Cache API の数えは厳密ではない。同時に来ると数え落とすし、
Cloudflare の拠点ごとに別勘定になる。素朴な連打を止めるには足りるが、本気の相手には足りない。

## 動かし方

```powershell
npx wrangler deploy          # 公開
npx wrangler tail            # ログを見る
npx wrangler tail --format pretty                    # 確保の様子を見る

# 台帳の中身は窓口ごしにしか見えない（＝管理画面を持たない作り）。
#   /v1/check?n=61 で、その数字の使用済み件数と次の空き文字が分かる
```

## 割り切った点

- **番号を持つのは「人」ではなく「端末」。** ログインがないため、再発行キーを失うと取り戻せず、
  その番号は埋まったまま残る。キーは記録の書き出し（JSON）に含まれる
- **「別の番号にする」と、前の番号は埋まったまま。** 返却の窓口を作っていない
- ~~同時に確保すると、まれに同じ文字が2人に出る可能性がある~~ → **解消済み**（Durable Objects へ移行）
- **台帳を一覧する手段がない。** 窓口は数字ごとの確認しか返さないため、
  全体で何件登録されたかを知る手立てを持っていない（持たせると個人の特定に近づくため、意図して置いていない）
- **アクセス元のIPはCloudflare側に記録される。** 市の制作物にする段階では、
  外部サービス利用（情報セキュリティポリシー 8.3／8.4）の判断対象になる
